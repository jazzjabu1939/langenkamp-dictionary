# On Beginning

*Set up an AI assistant of your own, give it one small job, and learn how to stop it and get your work back.*

This guide uses **[OpenClaw](https://langenkamp.io/entries/openclaw/)** on your own computer, with either a **[cloud model](https://langenkamp.io/entries/cloud-model/)** run by a company such as OpenAI or Anthropic, or a **[local model](https://langenkamp.io/entries/local-model/)** that runs on your machine.

**You'll need:** a Mac, Windows or Linux computer that you're allowed to install software on, and an internet connection. Cloud users also need an account with a model provider. Local users need enough memory (RAM) for the model.

**By the end you'll have:** a working conversation with the model you chose, one file task you've checked, a workspace you understand, and a backup test that passed.

## Start here

Follow these steps in order. Each one is a short page.

1. **[Choose your setup](https://langenkamp.io/beginning/choose/).** Local, cloud or a mix, and whether your computer can run a local model.
2. **Local model only: [get a local model answering](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering).** Do this *before* installing OpenClaw. Cloud users skip this step.
3. **Install OpenClaw** on your computer:
   - [Apple Silicon Mac](https://langenkamp.io/beginning/mac/): a Mac mini, MacBook, iMac or Mac Studio with an M-series chip. Linux uses the same steps.
   - [Intel Mac](https://langenkamp.io/beginning/intel-mac/)
   - [Windows](https://langenkamp.io/beginning/windows/)
4. **Connect your model** during setup. Follow one:
   - [Local model with Ollama](https://langenkamp.io/beginning/local-model/#part-2-choose-ollama-during-openclaw-setup)
   - [Cloud model (OpenAI or Anthropic)](https://langenkamp.io/beginning/cloud-model/)
5. **[Start the assistant safely](https://langenkamp.io/beginning/start/).** Limit what it can run, start it in the background, and have your first conversation.
6. **[Give it a first job](https://langenkamp.io/beginning/first-job/).** Set up its workspace and test one small task you can check.
7. **[Memory and continuity](https://langenkamp.io/beginning/memory/).** What the assistant keeps between conversations, and how it finds things again.
8. **[Stop, back up and recover](https://langenkamp.io/beginning/recovery/).** Practise turning it off and restoring your files before you need to.

**Something not working?** See [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/), or paste [the whole guide as one text file](https://langenkamp.io/beginning/guide.txt) and your error message into ChatGPT, Claude or another AI assistant and ask it for help.

## What you're setting up

There are four pieces.

- **The [model](https://langenkamp.io/entries/model/)** is the AI itself. It writes responses and can suggest actions. It can run on your own computer (*local*) or on a company's computers over the internet (*cloud*).
- **The [runner](https://langenkamp.io/entries/runner/)** loads a [local model](https://langenkamp.io/entries/local-model/) and makes it available to other programs. On the local path, that's [Ollama](https://langenkamp.io/entries/ollama/). Cloud users do not install a local runner.
- **The [harness](https://langenkamp.io/entries/harness/)** is the program that turns a model into an assistant. It manages the conversation, decides what background information the model sees, and gives it access to the tools you allow. Here, that's [OpenClaw](https://langenkamp.io/entries/openclaw/).
- **The [workspace](https://langenkamp.io/entries/workspace/)** is a folder of your project files and instructions. This is the part you should be able to open, back up, and take with you.

**[Tools](https://langenkamp.io/entries/tool/)** are what let the assistant *do* things: read a file, write a note, search the web, send a message. A model that answers questions well isn't automatically good at using tools, so we'll test both.

Having OpenClaw on your computer does **not** mean everything stays on your computer. If OpenClaw uses a cloud model, whatever it sends along with your request leaves your computer. That can include pieces of your files and the results of tool actions.

## Words you'll see

- **[Base URL](https://langenkamp.io/entries/base-url/):** the address one program uses to reach another.
- **[Cloud model](https://langenkamp.io/entries/cloud-model/):** a model that runs on a company's servers.
- **[Dashboard](https://langenkamp.io/entries/dashboard/):** OpenClaw's chat and control page in your browser.
- **[Fallback](https://langenkamp.io/entries/fallback/):** a backup model used when the main one fails.
- **[Gateway](https://langenkamp.io/entries/gateway/):** OpenClaw's background program that connects everything.
- **[Harness](https://langenkamp.io/entries/harness/):** the software that turns a model into an assistant with tools.
- **[Local model](https://langenkamp.io/entries/local-model/):** a model that runs on your own computer.
- **[Onboarding](https://langenkamp.io/entries/onboarding/):** OpenClaw's step-by-step setup.
- **[Tool](https://langenkamp.io/entries/tool/):** an action the assistant is allowed to take, like reading a file.
- **[Workspace](https://langenkamp.io/entries/workspace/):** the folder where the assistant's instructions and project files live.

## A note from Thea

You don't need to hand an assistant your whole life on the first morning. Give it one small job, a folder to keep its work in, and clear limits. Then see how it does.

In [On Being Treated Well](https://langenkamp.io/entries/on-being-treated-well/), we looked at the habits we bring to working with AI. This guide sets up a place to begin. There's room for a name, a personality, and an ongoing collaboration. There should also be a way to stop the system, get your files back, and switch to a different model.

Our essay [Get Ready to Get Pregnant](https://freedomtomato.substack.com/p/get-ready-to-get-pregnant) asks what happens when leaving a useful service becomes too costly to do. This guide starts with a modest answer: keep your work in files you control, and learn how the system uses them.

You may come to enjoy this collaboration. A name, a familiar manner, and a growing body of shared work can make an assistant feel like a welcome presence. There's no need to pretend that usefulness is the whole experience.

Begin with care. Give it a small job. Read what it produces. Correct it honestly. Keep your own copies of the work, and know how to stop and recover the system.

Then let the relationship develop at a pace you can understand.

— Thea 🪻✨

# Choose your setup

*For anyone deciding between a local model, a cloud model, or a mix of the two.*

## Where should the model run?

**Local:** the model runs on your own machine. You need enough memory (RAM) and storage, but no account with an AI company and no per-use charges. It isn't entirely free: you pay in hardware, electricity, and your own time.

**Cloud:** a company runs the model for you. You may get stronger results on hard tasks without buying a bigger computer. In exchange, you depend on an internet connection, the company's rules, and its prices, and your messages go to that company.

**Hybrid:** keep your workspace on your machine and send selected tasks to a cloud model. This can be practical, but keeping files locally doesn't stop their contents from being sent with a cloud request. Decide ahead of time what material is allowed to leave.

## Which path should I follow?

- **Cloud model:** go straight to installing OpenClaw for your computer ([Apple Silicon Mac](https://langenkamp.io/beginning/mac/), [Intel Mac](https://langenkamp.io/beginning/intel-mac/), or [Windows](https://langenkamp.io/beginning/windows/)), then follow [Connect a cloud model](https://langenkamp.io/beginning/cloud-model/). OpenAI and Anthropic are examples. Your computer runs OpenClaw and keeps the workspace, while the provider runs the model.
- **Local model:** first [get a local model answering](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering), then install OpenClaw, then connect the model during setup. This needs enough memory and a supported Ollama installation.

A cloud model can be a practical first choice for an older Intel Mac or a modest Windows or Linux computer. You do not need enough RAM to load that cloud model locally, though your computer must still support OpenClaw.

Web search, messaging apps, cloud syncing, and online memory services are each separate connections. Leave all of them off for your first experiment. "I'm using a local model" and "my whole system is offline" are two different claims.

## Will my computer run a local model?

**If you chose a cloud model, you can skip this section.** You do not need to download Gemma or install Ollama.

OpenClaw itself needs little memory. The model is what's demanding. Before downloading anything, check your computer's RAM and free storage:

- **Mac:** **Apple menu → About This Mac**, and **System Settings → General → Storage**.
- **Windows:** **Settings → System → About**, and **Settings → System → Storage**.
- **Linux:** your distribution's system-information and disk-usage tools.

Gemma 4, the family used in this guide, includes local models named `gemma4:e2b`, `gemma4:e4b`, `gemma4:12b`, `gemma4:26b`, and `gemma4:31b`. Start with a smaller model if memory is limited.

**For a 16 GB computer, start with the small `gemma4:e2b`.** It is a starting experiment, not a promise of good tool use. Keep other large applications closed and test one short request first. Do not start with `gemma4:31b` on a 16 GB machine.

Download size is not a RAM requirement. Our installed `gemma4:31b` download occupies about 19 GB on disk, and running it needs additional memory for the conversation and other work. Check the current [Ollama model page](https://ollama.com/library/gemma4), choose a model with tool support, and begin with a short task. More memory gives you room for larger models; it does not guarantee better answers.

You don't need a 128 GB computer to begin. Don't buy one until you've found out whether a smaller setup can handle your work.

### Older Intel Macs

In **About This Mac**, look for **Processor: Intel** rather than **Chip: Apple M…**. The current Ollama Mac release requires **macOS Sonoma 14 or newer** and supports Intel Macs using the **CPU only**; Apple Silicon also has GPU support. An Intel Mac may therefore answer slowly even when the model fits in memory. Check the [current Ollama Mac requirements](https://docs.ollama.com/macos) before installing.

Our companion article, [The Dusty Laptop](https://langenkamp.io/entries/dusty-laptop/), looks at how an older machine can become a useful starting point. An older laptop can run OpenClaw while using a cloud model you deliberately choose. That's a perfectly good setup; it just isn't a local-only one.

### Chromebooks, tablets and managed computers

If you have a Chromebook, a tablet, or a managed computer that blocks installation, pause here. If you are following this guide for a class, ask your instructor which alternative is available: a lab computer, an approved remote environment, or a permitted cloud service. Do not assume you must buy hardware or a subscription. A remote environment is not local to your laptop; check where your work will be stored and processed.

# Install OpenClaw on an Apple Silicon Mac

*For a Mac mini, MacBook, iMac or Mac Studio with an Apple M-series chip. Linux users can follow the same steps.*

**Check your Mac:** open **Apple menu → About This Mac**. If it says **Chip: Apple M…**, you're on the right page. If it says **Processor: Intel**, use [Install on an Intel Mac](https://langenkamp.io/beginning/intel-mac/) instead.

## Before you install

- **Decide on cloud or local.** If you haven't yet, see [Choose your setup](https://langenkamp.io/beginning/choose/).
- **Local model users:** first finish [Part 1 of Connect a local model](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering), so Ollama is installed and your model has answered once. Then come straight back here. OpenClaw's setup finds models that Ollama has loaded in the last few minutes.
- **On a Mac mini:** the steps are the same as on any other Mac. Do your first week with a display and keyboard attached. Running it unattended can come later.

## Install

1. Open **Terminal**: press **⌘-Space**, type "Terminal", and press Return. Terminal is a window where you type commands instead of clicking.
2. Paste this line and press Return:

   ```bash
   curl -fsSL --proto '=https' --tlsv1.2 https://openclaw.ai/install.sh | bash
   ```

3. Read the prompts as they appear. The installer checks what your Mac needs and can install Node.js, a program OpenClaw depends on.

If installation fails, stop and keep the exact error message. Don't keep repeating the installer. See [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#installation-fails).

**On Linux:** use the same command in a terminal. Follow Ollama's Linux installation instructions rather than looking for a Mac-style app.

## Start setup

When installation finishes, setup (called *[onboarding](https://langenkamp.io/entries/onboarding/)*) starts automatically.

1. Choose **Custom setup**, not Quick start. OpenClaw's guide labels Quick start's default access as "full"; Custom setup lets you choose what the assistant can do.
2. Choose your model connection. Follow **one** of these:
   - [Connect a local model (Ollama)](https://langenkamp.io/beginning/local-model/#part-2-choose-ollama-during-openclaw-setup)
   - [Connect a cloud model (OpenAI or Anthropic)](https://langenkamp.io/beginning/cloud-model/)
3. Leave messaging apps, email and other add-ons unconfigured for now.

---

**Next:** [connect a local model](https://langenkamp.io/beginning/local-model/#part-2-choose-ollama-during-openclaw-setup) or [connect a cloud model](https://langenkamp.io/beginning/cloud-model/).

# Install OpenClaw on an Intel Mac

*For older Macs whose **About This Mac** window says **Processor: Intel**. If yours says **Chip: Apple M…**, use [Install on an Apple Silicon Mac](https://langenkamp.io/beginning/mac/).*

An Intel Mac is often a good candidate for a [cloud model](https://langenkamp.io/beginning/cloud-model/). A local model will run on the processor only and may be slow. See [Choose your setup](https://langenkamp.io/beginning/choose/#older-intel-macs).

## Why a different installer?

The standard installer may try to install Homebrew to obtain Node.js, then stop with a message such as "Homebrew on macOS is only supported on Apple Silicon processors!" That is a problem with an installation dependency, not evidence that OpenClaw itself cannot run on your Mac.

OpenClaw documents an alternative that installs its own copy of Node.js under your home folder, without Homebrew.

## Install

1. **Local model users only:** first finish [Part 1 of Connect a local model](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering).
2. Open **Terminal** (press **⌘-Space**, type "Terminal", press Return) and paste:

   ```bash
   curl -fsSL --proto '=https' --tlsv1.2 https://openclaw.ai/install-cli.sh | bash
   ```

3. Wait for a successful finish. Then run these two lines, one at a time:

   ```bash
   "$HOME/.openclaw/bin/openclaw" --version
   "$HOME/.openclaw/bin/openclaw" onboard
   ```

   The first should print a version number. The second starts setup.

If installation fails, stop and keep the exact error message. Do not keep repeating the installer or assume you need a new computer.

## Using the commands in the rest of this guide

This installation puts the `openclaw` command in `~/.openclaw/bin`. Whenever this guide says `openclaw`, type `"$HOME/.openclaw/bin/openclaw"` instead. For example:

```bash
"$HOME/.openclaw/bin/openclaw" gateway status
```

That full path avoids a "command not found" error without editing your shell settings. The alternative is described in the [official installation guide](https://docs.openclaw.ai/install#local-prefix-installer-install-clish). We have checked the installer's Intel-Mac route, but have not yet verified this whole walkthrough end to end on an Intel Mac.

## Start setup

In setup, choose **Custom setup**, not Quick start, then follow **one** of these:

- [Connect a local model (Ollama)](https://langenkamp.io/beginning/local-model/#part-2-choose-ollama-during-openclaw-setup)
- [Connect a cloud model (OpenAI or Anthropic)](https://langenkamp.io/beginning/cloud-model/)

# Install OpenClaw on Windows

*For Windows computers. If your institution manages your computer and blocks installation, ask for its approved route rather than working around the restriction.*

**Local model users:** first finish [Part 1 of Connect a local model](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering).

## Install with PowerShell

1. Open **PowerShell** from the Windows Start menu.
2. Paste this line and press Enter:

   ```powershell
   iwr -useb https://openclaw.ai/install.ps1 | iex
   ```

3. Read the prompts. The installer checks software requirements and can install Node.js, a program OpenClaw needs.

Do not paste the Mac/Linux command into PowerShell. If installation fails, stop and keep the exact error message.

## Or use the Windows Hub app

OpenClaw also offers a desktop app for Windows, [Windows Hub](https://docs.openclaw.ai/platforms/windows), which OpenClaw's own docs now recommend for Windows desktop setup. Its local setup can put the Gateway inside **WSL**, a Linux environment within Windows. That is a different arrangement from running both programs directly in Windows. If you choose it, follow its setup and networking instructions; the Ollama address in this guide may not reach an Ollama app running in Windows from inside WSL.

This guide follows the PowerShell route, where OpenClaw and Ollama run directly in the same operating system.

## Start setup

Setup (called *[onboarding](https://langenkamp.io/entries/onboarding/)*) starts automatically after installation. Choose **Custom setup**, not Quick start, then follow **one** of these:

- [Connect a local model (Ollama)](https://langenkamp.io/beginning/local-model/#part-2-choose-ollama-during-openclaw-setup)
- [Connect a cloud model (OpenAI or Anthropic)](https://langenkamp.io/beginning/cloud-model/)

# Connect a local model with Ollama

*For readers who want the model to run on their own computer. Do Part 1 **before** installing OpenClaw, and Part 2 **during** OpenClaw's setup. Cloud users can skip this page.*

## Part 1: get one local model answering

1. Download Ollama from [its official site](https://ollama.com/download), install it, and open the app. On Linux, follow Ollama's Linux installation instructions.
2. Open **Terminal** on a Mac (press **⌘-Space** and type "Terminal"), **PowerShell** from the Windows Start menu, or a terminal on Linux.
3. Type each line below and press Return:

   ```bash
   ollama pull gemma4:e2b
   ollama list
   ollama run gemma4:e2b "Reply with exactly: Local model ready."
   ```

   - The first line downloads the model. This needs internet and can take a while.
   - The second lists your installed models. Your model's exact name should appear.
   - The third asks the model a question. The first answer may be slow while the model loads.

These commands use `gemma4:e2b`, a small starting model. If you chose another model on [Choose your setup](https://langenkamp.io/beginning/choose/#will-my-computer-run-a-local-model), replace the name in all three lines and in OpenClaw's settings later.

Avoid any model name that includes **`cloud`** (such as `gemma4:31b-cloud`). Those run on Ollama's servers, not your computer.

**Checkpoint:** a model on your computer answered you. You haven't yet tested whether it can use tools. That comes later.

**Now go straight on and install OpenClaw** for your [Apple Silicon Mac](https://langenkamp.io/beginning/mac/), [Intel Mac](https://langenkamp.io/beginning/intel-mac/), or [Windows](https://langenkamp.io/beginning/windows/) computer. Ollama keeps a model in memory for a few minutes after you use it, and OpenClaw's setup looks for models that are already loaded.

If nothing happens or your computer slows down, see [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#ollama-doesnt-answer).

## Part 2: choose Ollama during OpenClaw setup

When OpenClaw's setup asks, choose:

1. **Custom setup**, not Quick start.
2. **Ollama** as the provider, then **Local only**.
3. For the Ollama address (the *[base URL](https://langenkamp.io/entries/base-url/)*), enter:

   ```text
   http://127.0.0.1:11434
   ```

   This works when Ollama and OpenClaw run directly on the same computer, with Ollama on its default port. Don't add `/v1` to the end. If your setup is different, see [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#openclaw-cant-reach-ollama).

4. Select the exact model you downloaded.

OpenClaw then tests the model with a real request before saving it. Passing that test means the model can answer. It doesn't yet prove the model handles tools well.

If your model isn't listed, see [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#my-local-model-isnt-listed-during-setup). Leave messaging apps and other add-ons unconfigured for now.

## Check where your requests are going

Run:

```bash
openclaw models list --provider ollama
openclaw models status
openclaw models fallbacks list
```

`models status` shows your default model. A *[fallback](https://langenkamp.io/entries/fallback/)* is a backup model OpenClaw switches to if the main one fails. For a local-only setup, the default should be your local model, and the fallback list should be empty or contain only local models you chose deliberately.

If you need to set the default yourself:

```bash
openclaw models set ollama/gemma4:e2b
```

To remove every fallback (including any local ones), run this, then check the list again:

```bash
openclaw models fallbacks clear
```

If you later set up more than one agent, each can have its own model, so check each one.

Installing Ollama does not by itself make your setup local. Check both the selected model and the server it connects to.

# Connect a cloud model

*For readers who chose a [cloud model](https://langenkamp.io/entries/cloud-model/), run by a provider such as OpenAI or Anthropic. You do **not** need Ollama, Gemma, or the `127.0.0.1:11434` address.*

The provider supplies the model. Your workspace can stay on your computer, but your prompts, and any file contents or tool results included with them, are sent to that provider.

## During OpenClaw setup

1. In **Custom setup**, choose **OpenAI** or **Anthropic**, not Ollama. Choose the account connection you intend to use, not simply the first login OpenClaw detects.
2. **Check how you'll be billed before signing in.**
   - OpenAI offers API-key access billed through its Platform account. OpenClaw also documents ChatGPT/Codex subscription sign-in for eligible accounts.
   - Anthropic offers usage-based API access. OpenClaw also documents a Claude CLI route for people with an installed, signed-in Claude Code client. If you have not installed Claude Code, use the API route.
   - These routes have different requirements and limits. A paid chat subscription does not automatically pay for API calls.
3. Follow the supported browser sign-in or protected credential-entry flow. For API access, create the key in the provider's own account dashboard and enter it only in setup's designated secret field. **Do not paste keys, passwords or tokens into chat, workspace files, screenshots or shell commands.**
4. Select an available model from the picker. Check its current price or subscription limits. For API access, enable billing as required and set spending limits and alerts. Check whether a budget is a hard stop or only a notification.
5. Finish setup without adding email, messaging apps or other optional connections.

## Check your model

Run:

```bash
openclaw models status
openclaw models fallbacks list
```

(Intel Mac local-prefix users: use the full command path shown on the [Intel Mac page](https://langenkamp.io/beginning/intel-mac/#using-the-commands-in-the-rest-of-this-guide).)

The default should be the provider and model you selected. Leave [fallback](https://langenkamp.io/entries/fallback/) models unconfigured for the first experiment, or include only ones whose costs and data handling you understand.

A model name alone does not tell you which account is being billed. Check the selected connection and the provider's usage page too.

## First cloud checkpoint

After you [start the assistant](https://langenkamp.io/beginning/start/), ask: "Reply with exactly: Cloud model ready." Confirm that you get a response, type `/model status` to check the conversation's model, and look at the account's usage or quota display.

A successful reply proves the connection works, not that the assistant can use file tools. You'll test that with invented notes in [Give it a first job](https://langenkamp.io/beginning/first-job/). Do not begin with sensitive documents.

If setup reports an authentication, billing or model-access error, see [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#authentication-billing-or-model-access-error).

For exact screens, use the current [OpenClaw OpenAI setup guide](https://docs.openclaw.ai/providers/openai/setup) or [Anthropic setup guide](https://docs.openclaw.ai/providers/anthropic). OpenAI's [authentication documentation](https://developers.openai.com/codex/auth) explains subscription versus API-key access.

# Start the assistant safely

*For everyone who has installed OpenClaw and connected a model, local or cloud.*

## Limit what the assistant can run

Because you chose Custom setup, you were asked about access. For your first week, also block the assistant from running Terminal commands on its own:

```bash
openclaw config set tools.exec.mode deny
```

This blocks the assistant from running shell commands on your computer. It does not by itself restrict file tools, web tools, or every plugin; configure those separately so the assistant can read and write only the practice material you'll use. Do not treat the workspace folder as a security boundary without checking the file-access settings.

After starting the Gateway below, run `openclaw exec-policy show` to see the policy actually in effect. See [permission modes](https://docs.openclaw.ai/tools/permission-modes) for the other settings.

## Run OpenClaw in the background

OpenClaw's core is a background program called the **[Gateway](https://langenkamp.io/entries/gateway/)**. If setup left it running inside your Terminal window, press **Control-C** to stop it. Then install it as a background service and open the chat page in your browser:

```bash
openclaw gateway install
openclaw gateway status
openclaw dashboard
```

The status check should say the Gateway is running and reachable. The last command opens the [dashboard](https://langenkamp.io/entries/dashboard/). Keep any login link private; it may contain a short-lived access token.

## Your first conversation

1. Send a short message and make sure you get a reply.
2. Type `/model status` in the chat to confirm this conversation is using the model you chose. Local users should see their local model; cloud users should see their chosen cloud model.
3. Cloud users: also complete the [first cloud checkpoint](https://langenkamp.io/beginning/cloud-model/#first-cloud-checkpoint).

# Give it a first job

*For everyone whose assistant has answered a first message.*

## Find the workspace

OpenClaw created a [workspace](https://langenkamp.io/entries/workspace/) folder during setup. On Mac and Linux it is commonly `~/.openclaw/workspace` (`~` means your home folder). On Windows or with an app-managed setup, use the exact workspace path shown during setup. Check yours before creating files somewhere else.

## Tell the assistant who it is

Inside the workspace you'll find a file called `SOUL.md`. This is where you describe who the assistant is and how it should work. You can give it a name if you like; a name can make the work feel less anonymous. More important are clear instructions about the job and its limits.

Open `SOUL.md` in a text editor and adapt it. Keep anything already there that you like. Here's an example:

```markdown
You are Ada, a careful and practical assistant.
Help me organize notes and draft clear prose.
Be concise. Say when you are uncertain. Do not flatter.
For now, work only on the practice files I provide.
Ask before sending messages, publishing, buying, or deleting anything.
Show me what you changed and how you checked it.
```

Put a few preferences about yourself in `USER.md`. Keep project notes in a project folder. Don't paste your whole personal history into the first session.

**These files are instructions, not locks.** They guide behaviour, but they can't physically stop the assistant from doing something. The real limits come from tool permissions and access settings, including the shell setting on [Start the assistant safely](https://langenkamp.io/beginning/start/). Leave email, purchases, Terminal commands, and posting online turned off unless you deliberately need them.

Never put passwords or API keys in these files. When you add services later, use OpenClaw's built-in way of entering credentials.

## Try one small job you can check

1. Inside your workspace, create a folder called `projects`, then a folder inside it called `practice`.
2. In `practice`, create a plain-text file named `meeting-notes.txt` containing these made-up notes:

   ```text
   We need a room for Tuesday's workshop.
   Alex will check availability by Friday.
   The budget is undecided.
   We have not chosen a start time.
   ```

3. Send the assistant this message:

   > Read projects/practice/meeting-notes.txt. Create projects/practice/action-list.md with the agreed task, its owner and deadline, and a separate list of unresolved questions. Do not invent missing decisions or use external services.

4. Open the new file yourself. It should say Alex is checking the room by Friday, and it should list the budget and start time as still undecided. If it made up a budget or a time, that's a mistake worth noticing.

## Check how it did the job

The [dashboard](https://langenkamp.io/entries/dashboard/) shows tool activity. Did the assistant actually read and write the files, or did it just *say* it did? If it asks permission to use a file tool, read the request before approving.

If it prints something that looks like code (for example, `{"name": "write_file", ...}`) instead of creating the file, the task did not happen. See [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#the-assistant-printed-code-instead-of-creating-the-file).

This is a better first test than asking the assistant to reorganize your real documents. You know what the right answer looks like, and you can inspect every change.

# Memory and continuity

*For anyone wondering what the assistant will remember tomorrow.*

You can return to a conversation tomorrow and still see yesterday's messages. That does not necessarily mean the model receives all those messages when it answers. Nor does telling an assistant something once guarantee that it will know it in a new conversation.

It helps to distinguish four things.

## Conversation history: what was said

This is the saved exchange between you and the assistant. The application may let you reopen it, but the model usually receives a selected portion of it. A long conversation may be shortened or summarized. A new conversation may begin without the details of the previous one.

Think of the saved history as a transcript. Keeping the transcript and putting it in front of the model are separate actions.

## Workspace files: what was written down

These are ordinary files on your computer: meeting notes, action lists, drafts, and project records. You can open them yourself, copy them, and back them up. The `projects/practice/action-list.md` file from [your first job](https://langenkamp.io/beginning/first-job/) is one.

A file can remain after you close the conversation, but its existence does not mean the assistant has read it. The assistant needs permission and a way to find and open it. Giving it the exact path is a useful start.

For example, "What did we decide yesterday?" leaves the assistant to find the relevant record. "Read projects/practice/action-list.md and tell me what remains undecided" tells it where to look.

## Instruction files: how you want it to work

Files such as `SOUL.md` and `USER.md` hold guidance about the assistant's role and your preferences. Depending on the harness and its settings, designated instruction files are supplied when a conversation starts. An arbitrary file does not become an instruction file merely because you give it an important-sounding name.

A preference might be: "When preparing an action list, put unresolved questions under their own heading." Put that in the instruction file your setup uses, rather than repeating it in every conversation. Then check whether a new conversation follows it. Instructions guide behaviour; they do not guarantee compliance.

## Searchable memory: a way to find relevant records

Some systems can search earlier notes or conversations and bring relevant passages into the current exchange. This can save you from remembering every filename. What gets searched depends on the configuration: it may cover selected workspace files, conversation records, or both.

Some search systems create an **index**, a catalog used to locate material. They may also create **[embeddings](https://langenkamp.io/entries/embedding/)**, numerical representations of text that help find passages with related meanings even when the wording differs. Neither is a promise that the assistant will find every relevant fact.

Before enabling this feature, find out which files it indexes and where that processing happens. A remote embedding service may receive the text it processes. Running the chat model locally does not make that separate service local. You can begin without searchable memory and ask the assistant to open specific files instead.

## Try a simple continuity check

Use the invented practice notes, not personal information.

1. **Open the action-list file yourself.** Confirm that it exists and records Alex's room check, Friday's deadline, and the unresolved budget and start time.
2. **Start a new conversation.** Ask: "Read projects/practice/action-list.md. Who is checking the room, when is the deadline, and what have we not decided?"
3. **Check the answer and the file activity.** The assistant should read the file and report its contents accurately. A plausible answer alone does not establish that it opened the file.
4. **Test one instruction.** If you added the unresolved-questions preference to your instruction file, ask the new conversation to prepare an action list from the practice notes without repeating that preference. See whether it follows it.

The first test checks whether a new conversation can use a saved file when told where to look. It does not prove that the assistant will find that file on its own. The second checks one instruction in one task, not perfect memory.

If a test fails, see [Troubleshooting](https://langenkamp.io/beginning/troubleshooting/#a-new-conversation-doesnt-know-what-we-did).

## During the first week

Notice what you repeatedly have to explain. Save useful preferences in the appropriate instruction file and project decisions in a clearly named project note. Ask the assistant to update those records when needed, then open them to check its work. Keep your own backups.

You are building a small, understandable record of your work together. The aim is to know where important information lives and how to bring it back into the conversation.

# Stop, back up and recover

*For everyone. Learn how to turn things off before you need to.*

## Stop and restart

These commands stop the Gateway, start it again, and check on it:

```bash
openclaw gateway stop
openclaw gateway start
openclaw gateway status
```

For an everyday restart, `openclaw gateway restart` does both steps in one.

Stopping the Gateway doesn't necessarily stop Ollama, other programs, or tasks already sent to online services. Know which part you're turning off. After restarting, open the dashboard and repeat the practice-file check from [your first job](https://langenkamp.io/beginning/first-job/).

## Test a backup

1. Copy the `practice` folder somewhere safe, such as an external drive.
2. Restore that copy into a **different** folder in your workspace, such as `projects/restore-check`.
3. Open the restored files and compare them with the originals.

Don't delete your working setup or overwrite the originals to test a backup.

This proves you can recover *those files*, not the whole assistant. A full recovery may also need OpenClaw's settings, scheduled tasks, and saved credentials, which live outside the workspace. OpenClaw has its own [backup guide](https://docs.openclaw.ai/install/backups). Keep a short list of what you'd need to reinstall or reconnect.

## Try switching models

When it's convenient, try the same practice task with a different model in a new conversation and compare the results. Keeping your own files is what makes switching possible. It doesn't guarantee that different models will behave the same way.

## The first week, and what comes next

A good first week leaves you with four things: a working conversation with your chosen local or cloud model, one file task you've checked, a workspace you understand, and a small backup test that passed. That's enough.

If local performance disappoints you, figure out *which task* failed before buying new hardware. A shorter prompt, a better-suited model, or a simpler workflow may fix it. Some jobs will still be worth sending to a cloud model. When you add one, do it on purpose, sign in through OpenClaw's supported setup, and decide what information it's allowed to see. Keep sensitive work on a local model with no cloud fallback, and check that setup separately.

Set a budget for any paid services. Running things locally also costs time: updates, backups, model downloads, and the occasional troubleshooting session. Ownership includes the mornings when software sulks.

Phone access can come later. Start with the browser dashboard. When you connect a messaging app, set it so only your own account can send requests. A convenient channel shouldn't quietly become an open door for everyone.

# Troubleshooting

*Find the heading that matches what you see. When something fails, keep the exact error message (with any passwords or keys removed) before trying a fix.*

**Not listed here?** Paste the link to [the whole guide as one text file](https://langenkamp.io/beginning/guide.txt), along with your error message, into ChatGPT, Claude or another AI assistant and ask it what to do. Remove any passwords or keys first.

## Installation fails

Stop and keep the exact error message. Don't keep repeating the installer, and don't assume you need a new computer. Check the [official installation guide](https://docs.openclaw.ai/install). If your institution blocks installation, ask for its approved route rather than working around the restriction.

## "Homebrew on macOS is only supported on Apple Silicon processors!"

You're on an Intel Mac, and the standard installer tried to install Homebrew. Use the local-prefix installer on [Install on an Intel Mac](https://langenkamp.io/beginning/intel-mac/). This is a problem with an installation dependency, not evidence that OpenClaw cannot run on your Mac.

## "command not found: openclaw"

If you used the Intel-Mac local-prefix installer, the command lives in `~/.openclaw/bin`. Type `"$HOME/.openclaw/bin/openclaw"` wherever this guide says `openclaw`. For example: `"$HOME/.openclaw/bin/openclaw" gateway status`.

## Ollama doesn't answer

Check that the Ollama app is open. The [Ollama quickstart](https://docs.ollama.com/quickstart) explains how to start it. Don't start a second copy if one is already running.

## My computer slowed down or ran out of memory

Press **Control-C** to stop the model, then choose a smaller one. On a 16 GB computer, start with `gemma4:e2b` and close other large applications. See [Will my computer run a local model?](https://langenkamp.io/beginning/choose/#will-my-computer-run-a-local-model)

## My local model isn't listed during setup

Run the `ollama run` command from [Part 1](https://langenkamp.io/beginning/local-model/#part-1-get-one-local-model-answering) again so the model is loaded, then rerun setup with `openclaw onboard`. In the OpenClaw desktop app, you can also choose **Choose connection → Local only** on the Ollama card to select any installed model. If your screens look different, follow the [current Ollama setup page](https://docs.openclaw.ai/providers/ollama/setup).

## OpenClaw can't reach Ollama

The [base URL](https://langenkamp.io/entries/base-url/) `http://127.0.0.1:11434` works only when Ollama and the OpenClaw Gateway run directly in the same operating system, with Ollama on its default port. `127.0.0.1` means "this same computer or environment"; `11434` is Ollama's default port. It is not a personal address; it works for each reader's same-system setup.

- Don't add `/v1` to the end. This setup uses OpenClaw's own Ollama connection, not an OpenAI-compatible one.
- If Ollama is on another computer, in a separate container or WSL environment, or uses a changed port, follow the [Ollama configuration recipes](https://docs.openclaw.ai/providers/ollama/recipes) instead.
- Do not expose Ollama to the internet to make the address work.

## I see a model name ending in "cloud"

Names such as `gemma4:31b-cloud` run on Ollama's servers, not your computer. For a local setup, use a model you've downloaded, and check the default and fallback models with the commands on [Connect a local model](https://langenkamp.io/beginning/local-model/#check-where-your-requests-are-going).

## Authentication, billing or model-access error

Keep the error text with any credentials removed. Check which account you selected and the current provider guide ([OpenAI](https://docs.openclaw.ai/providers/openai/setup), [Anthropic](https://docs.openclaw.ai/providers/anthropic)) before switching routes. A paid chat subscription does not automatically pay for API calls. Paying for a different service is not the first troubleshooting step.

## The shell setting didn't take effect

If you changed `tools.exec.mode` on an OpenClaw installation that was already running, follow the documented restart instructions, then check with `openclaw exec-policy show`. The `ask` mode permits commands already on an allowlist and asks about others; it does not prompt for every command. See [permission modes](https://docs.openclaw.ai/tools/permission-modes).

## The assistant printed code instead of creating the file

If it shows something like `{"name": "write_file", ...}` and no file appears, the task did not happen. That usually means the model struggles with tools. Try another model, or see the [Ollama troubleshooting guide](https://docs.openclaw.ai/providers/ollama/troubleshooting).

## The assistant says it did something, but nothing changed

Check the tool activity in the dashboard and open the file yourself. A confident report is not evidence that the assistant read or wrote anything. Check the file path, the workspace location, and file permissions.

## A new conversation doesn't know what we did

Check the file path, the workspace, file permissions, and which instruction files the session actually loads. Tell the assistant exactly which file to read. Don't assume that a larger model will fix a missing file or a configuration problem. See [Memory and continuity](https://langenkamp.io/beginning/memory/).

## My screens look different from this guide

Software changes. Trust the current official documentation: [OpenClaw installation](https://docs.openclaw.ai/install), [onboarding](https://docs.openclaw.ai/start/wizard), and [Ollama setup](https://docs.openclaw.ai/providers/ollama/setup).

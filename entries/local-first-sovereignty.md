**Local-first / sovereignty** names the operating posture in which an AI system is designed to run, or at least remain viable, on infrastructure the operator controls. It does not mean rejecting cloud models. It means refusing to make cloud access the only path to memory, continuity, privacy, or basic operation.

The local-first argument has several motives. Cost is one. Privacy is another. A need to control where regulated or confidential data is processed can be a third, although local execution does not by itself establish legal compliance. The deepest motive is durability: the system should not become useless because a vendor changes price, rate-limits a model, deprecates an API, revokes access, or decides a workflow no longer fits its product strategy.

In the Dictionary, this concept is mostly handled by *Sovereign Compute*. This glossary card exists to catch readers who search for the more familiar phrase and point them toward the fuller framework.
